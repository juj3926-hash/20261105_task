# 비동기와 동기 비교 결과

같은 가상 장치에서 각 방식을 한 번씩 실행한 값이다. 근거는 `2026-11-05-async-control.md`, `2026-11-05-sync-control.md`의 로그다. 실행마다 값은 조금 달라질 수 있다.

| 항목 | 비동기 (`project.py`) | 동기 (`project_sync.py`) |
|---|---|---|
| 작업 순서 | A·B on 동시 → 양쪽 완료 → A·B off 동시 | A on → B on → A off → B off |
| 첫 on 요청부터 마지막 off 완료까지 | 8.0711초 | 12.2518초 |
| 정상 시 `observation` 최대 간격 | A 0.222초, B 0.221초 | A 4.047초, B 4.036초 |
| A 무응답 시 B on 요청 시각 | 0.0019초 | 1.5508초 |
| A 무응답 시 B on 완료 시각 | 4.0351초 | 5.6347초 |
| A 무응답 시 B `observation` 최대 간격 | 0.22초 | 4.593초 |
| on 실패 뒤 off 요청 | 없음 | 없음 |
| 복구 뒤 | 새 관측만 갱신, 새 명령 없음 | 새 관측만 갱신, 새 명령 없음 |

## 해석

- **시간:** 비동기는 단계마다 느린 B(4초)만큼 걸려 약 4+4초다. 동기는 지연이 더해져 약 2+4+2+4초다.
- **감시:** 동기판은 작업이 진행되는 동안 독립 감시가 실행되지 않아 간격이 작업 시간만큼 벌어진다. 비동기판은 약 0.2초 간격을 유지했다.
- **실패 영향:** 동기판에서는 A 조회와 A 작업의 0.5초 제한 대기가 차례로 쌓여 B 시작이 약 1.5초 늦었다. 비동기판에서는 A 실패가 B의 시작과 감시를 늦추지 않았다.

## 해석할 때 주의할 점

- 동기판의 공백은 독립 감시 흐름의 공백이다. `wait_output_sync` 내부에서는 해당 장치의 완료 확인용 status 조회가 계속되며, 다만 `observation`으로 기록되지 않는다.
- 이 결과는 단일 실행 흐름이라는 비교 조건의 결과다. 동기 통신을 쓰는 모든 프로그램이 동시 작업을 할 수 없다는 뜻은 아니다.
- 전체 시간에 초기화 시간과 작업 뒤 추가 감시 시간은 넣지 않았다.
